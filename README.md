# 将棋名人

盤面・候補手・読み筋・形勢をまとめて確認できる、PC・スマートフォン対応の将棋研究サイトです。AIの計算はブラウザ内で行います。APIキー、外部AIサービス、専用サーバー、ビルド作業は不要です。

## GitHubにアップロードして公開する

1. 配布ZIPを展開します。
2. GitHubで公開用のリポジトリを作成します。名前は `shogi-meijin` など、任意です。
3. **Add file → Upload files** を開き、展開したフォルダーの**中身**をすべてアップロードします。リポジトリの一番上に `index.html` が置かれ、`assets` と `engine-vendor` のフォルダー構成がそのまま残る状態にしてください。ZIPファイル自体を置くだけでは動きません。
4. **Commit changes** で `main` ブランチへ保存します。
5. **Settings → Pages → Build and deployment** で、Sourceを **Deploy from a branch**、Branchを **main**、Folderを **/(root)** にし、**Save** を押します。
6. Pagesに表示された公開URLを開きます。初回の公開には少し時間がかかります。

通常の公開URLは `https://ユーザー名.github.io/リポジトリ名/` です。更新時は変更したファイルを同じ場所に上書きしてコミットします。GitHub側がPages公開処理を行うので、独自のActionsワークフローは不要です。

詳しい公開方法: [GitHub公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 基本の使い方

- **手番**: 自分が先手か後手かを選びます。研究モードでは両者の指し手を盤面に入力できます。
- **研究モード**: 自分と相手の指し手を入力し、その局面からAIの候補手・読み筋・形勢を調べます。後手を選んだ場合は、まず相手の初手を入力します。
- **AI対局モード**: 自分の駒を動かすとAIが相手側を指します。後手を選べばAIが初手を指します。
- **駒の移動**: 駒を選択し、移動先を選びます。持ち駒は持ち駒欄で選択してから盤上を選びます。
- **成り**: 選択できる場合は確認画面で成る／成らないを選びます。必須の成りは自動で適用されます。
- **候補手**: AIが計算した上位候補を確認できます。推奨手の適用ボタンで、その手を盤面に反映できます。
- **戦法**: 選択した戦法の序盤の考え方をガイドします。相手の指し手によって適切な進行は変化するため、戦法ガイドが常に最善手を意味するわけではありません。
- **読み時間**: 1秒・3秒・8秒から選択します。長い設定ほど深く読める可能性がありますが、端末性能や局面によって変わります。
- **盤面反転・履歴**: 見る向きの変更、指し手の巻き戻し、履歴の確認に対応します。
- **局面の読み込み／保存**: SFEN形式、USIの `position ... moves ...` 形式、または本サイトが保存したJSONを読み込めます。書き出しは開始局面・USI指し手一覧・現在局面を含むJSON形式です。過去の手を表示中に保存すると、その手までを記録します。AI対局モードでAI手番の局面を読み込むと、AIが続きを指します。
- **終局**: 詰み・合法手なしを判定します。同一局面4回の千日手は引き分け、連続王手の千日手は王手を続けた側の負けとして扱います。棋譜を戻して検討を続けられます。

画面は幅に応じて再配置されます。スマートフォンでは主要情報をコンパクトにまとめ、補助情報は必要に応じてスクロールして確認できます。非常に小さな画面や文字拡大時はスクロールが必要です。

## AIと評価の意味

同梱エンジンは、やねうら王を単一スレッドWebAssemblyにしたビルドです。ニューラル評価関数は **SuishoPetite NNUE K-P（2021年11月）** を内蔵しています。最新版の評価関数や、あらゆる端末で世界最強となる構成をうたうものではありません。

- 評価値・形勢表示は、その時点の探索による目安です。実際の勝率の保証ではありません。
- 読みが進むと評価や候補手が変わることがあります。
- 詰み表示も探索結果です。画面に表示される読み筋と合わせて確認してください。
- 将棋に「どんな相手にも絶対に勝てる」と保証できるAIはありません。本サイトも勝利を保証しません。
- 戦法ガイドの説明と、エンジンが局面を計算した評価は区別して表示します。

エンジンの配布元・固定したソース・再ビルド手順・ライセンスは `engine-vendor` 内の説明を参照してください。`engine-vendor/yaneuraou-corresponding-source.tar.gz` は同梱バイナリに対応するソースです。再配布時も一緒に提供してください。

## 動作条件とデータ

WebAssembly SIMD、ES Modules、Web Workers（Worker内からのWorker生成を含む）を利用できる現行のブラウザが必要です。ブラウザの実装やメモリ制限によって利用できない端末があります。特定の実機すべてでの動作を保証するものではありません。

`index.html` をダブルクリックする `file://` 起動では、ブラウザの制限でAIやモジュールを読み込めない場合があります。GitHub PagesのHTTPS URL、または下記のローカルHTTPサーバーから開いてください。

局面などの保存にはブラウザのローカルストレージを使います。別端末へ自動同期されません。閲覧データの削除やプライベートブラウズでは保存内容が失われる場合があります。必要な記録は書き出してください。AIのために棋譜や局面を外部のAIサーバーへ送る構成ではありません。

## アイコン・OGP

オリジナルのブランドマーク、SVGファビコン、タッチアイコン、OGP画像を `assets` に同梱しています。

SNSでのプレビュー画像を確実に取得させるには、公開URLが決まってから `index.html` の `og:image` を `https://ユーザー名.github.io/リポジトリ名/assets/ogp.png` のような絶対URLに設定してください。独自ドメインを使う場合はそのURLに合わせます。必要に応じて `og:url` とcanonical URLも公開先に合わせて追加・更新してください。SNS側のキャッシュにより反映に時間がかかる場合があります。

## 開発・確認

Node.jsがある環境では、フォルダー内で次を実行できます。公開のために実行する必要はありません。

```sh
npm run dev
```

表示されたHTTPサーバーの `http://localhost:4173/` を開きます。

```sh
npm test
```

ルールなどの自動テストを実行します。
